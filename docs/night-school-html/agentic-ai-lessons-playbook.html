Agentic AI Lessons Learned & Best Practices Playbook

Goal

  • Capture operational lessons from running autonomous AI systems.
  • Provide Nova (and future agents) with repeatable patterns for reliability, maintainability, and safety.

Core Topics

| Topic | Why It Matters | Key Practices |

|-------|----------------|----------------|

| Memory Management | Prevents bloat, ensures relevant context. | • Distinguish Long‑term (MEMORY.md) vs Short‑term (daily logs).\n• Store only essential facts; prune expired items.\n• Use heartbeat to rotate out stale entries. |

| Error Recovery Patterns | Autonomous agents will encounter failures; graceful handling maintains trust. | • Wrap external calls in retries with exponential back‑off.\n• Circuit‑breaker: stop repeating failing actions after threshold.\n• Fallback to cheaper model or safe‑mode when critical errors occur. |

| Context Overflow Prevention | Model token limits cause truncation → loss of important info. | • Summarize daily logs into MEMORY.md weekly.\n• Chunk large tasks into sub‑agents (TaskFlow) with explicit hand‑offs.\n• Use compact_context utility (if available) before each model call. |

| Sub‑mind Communication Protocols | Multiple agents need coordinated state. | • Define a shared JSON schema for status (submind_state.json).\n• Use sessions_send with await to exchange messages synchronously.\n• Log all hand‑offs in AGENTS.md for audit. |

| Self‑Diagnosis & Maintenance Routines | Detect drift, resource leaks, or mis‑behaviour early. | • Heartbeat checks for CPU, memory, cost metrics.\n• Automated run‑book: nova self‑check → runs healthcheck skill.\n• Record findings in memory/heartbeat-state.json. |

| Escalation vs Local Handling | Know when to ask the human vs solve autonomously. | • Tiered decision matrix: \n 1️⃣ Low impact → auto‑resolve.\n 2️⃣ Medium impact → retry + log.\n 3️⃣ High impact → send alert (Discord/Email) before acting. |

| Model Selection Heuristics | Balance cost, speed, and quality. | • Follow SOUL.md tiering table.\n• Quick queries → qwen3:14b.\n• Complex code/debug → gpt-oss:120b.\n• Privacy‑sensitive → deepseek-r1. |

| Cron Job Reliability Patterns | Ensure scheduled tasks run predictably. | • Idempotent design – re‑running a cron should be safe.\n• Record last run timestamps in cron-state.json.\n• Use cron-model-tiering playbook to route heavy jobs to cheap models. |
