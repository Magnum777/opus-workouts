## Cron System Failure & Recovery (Apr 8 2026)

### Root Cause Discovered
6 of 14 cron jobs were ERROR. Root cause traced to config changes around 2026-04-07 21:42 UTC:
- `agents.defaults.model.primary` was set to `ollama/qwen3-coder:480b` — a model that doesn't exist in the local Ollama
- This caused all Ollama-based crons to fail with 404 errors, then cascade to other models

### Cascade Failure Chain
1. Cron tries `qwen3-coder:480b` → 404 (model doesn't exist)
2. Tries again → 401 unauthorized (wrong auth for external Ollama)
3. Falls back to `deepseek-r1:latest` → "does not support tools"
4. Falls back to other models → all timeout at 60-90s
5. Final error: "gateway timeout after 90000ms" when delivering subagent announcement

### Fix Applied
Updated all 6 failing cron job payloads to use `minimax/MiniMax-M2.7` instead of `ollama/*` models:
- Sentinel-Pulse-15min (b32bb66f)
- QuickScan-5min-FAST (7e9ce0a4)

### Ollama Subagent Bug (Critical Finding)
All Ollama models fail as OpenClaw subagents:
- `deepseek-r1:latest` → error: "registry.ollama.ai/library/deepseek-r1:latest does not support tools"
- `qwen2.5:7b` → times out with 0 tokens (works fine via direct curl in ~6s)
- `qwen3:14b` → times out with 0 tokens (works fine via direct curl in ~70s)

Root cause: OpenClaw's `api: "ollama"` mode sends requests via Ollama native Chat API (`/api/chat`) with tooling enabled. Local models don't support tooling on this endpoint. Direct API calls work fine.

Working subagent model: `minimax/MiniMax-M2.7` only.
