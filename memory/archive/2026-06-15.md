## Session 2 — Late Night / Early Morning (~12:30 AM - ~3:00 AM EDT)

### UniFi Guest Portal Fix
- Guest portal was NOT showing custom text despite API saying portal_customized: true
- Root cause: portal_customized flag wasn't being set properly via the custom script
- **Fix:** Used ez-unifi skill `raw PUT` with ALL fields including `portal_customized: true` in one request — stuck immediately
- Opus confirmed portal now shows: "Welcome to Sojourn Church", "Guest WiFi Access", Terms checkbox, "Connect to Internet" button
- **Lesson:** Use the skill's `raw` command for complex updates; custom scripts may silently fail on partial fields

### VLAN Creation Breakthrough
- Previous attempts failed with `api.err.WanIpOverlapped` referencing subnet `0.0.0.0/0`
- **Key discovery:** Creating VLANs with `purpose: "vlan"` AND `ip_subnet` fields triggers the WAN overlap bug
- **Workaround:** Two-step creation:
  1. Create as `purpose: "vlan-only"` (no IP fields) — succeeds
  2. PATCH to add `ip_subnet`, `dhcpd_start`, `dhcpd_stop`, `dhcpd_enabled` — succeeds
- Successfully created all 3 VLANs:
  - `sojourn-office` (VLAN 10): 192.168.10.1/24, DHCP .10-.250
  - `sojourn` (VLAN 20): 192.168.20.1/24, DHCP .10-.250  
  - `sojourn-guest` (VLAN 30): 192.168.30.1/24, DHCP .10-.250

### Rate Limiting
- Multiple rapid login attempts (custom scripts + skill auth) triggered rate limiting on UniFi controller
- Need ~2 minute cooldown between login attempts
- Cookie reuse helped briefly but sessions eventually expired too

### Still Needed (Daytime)
- Assign each SSID to its VLAN (update WLAN with networkconf_id)
- Test client segregation between VLANs
- Verify guest portal still works after VLAN assignment
- Check routing/firewall rules between VLANs

### Key Lesson
- UniFi controller has quirks: partial updates can silently fail, field ordering matters for VLAN creation, and rapid auth attempts trigger rate limits
- **Two-step creation pattern** works around the `WanIpOverlapped` bug for VLANs with static WAN configs

### WiFi Broke — VLANs Lack Layer 3
- Clients connecting to VLAN networks couldn't get IP addresses
- Root cause: `vlan-only` purpose creates VLAN tag but NO DHCP server or routing on USG
- USG needs corporate-purpose network to serve DHCP and route, but controller bug blocked that
- **Lesson:** vlan-only != functional network for WiFi clients. Need corporate purpose (which USG provides) for DHCP/Layer 3.

### Full VLAN Revert
- Deleted all 3 VLAN networks to restore connectivity
- Reassigned all 3 SSIDs back to Default network (`63753641922fab0fb7676948`)
- Accidentally disabled "Internet 2" (WAN2) during troubleshooting — noted for later re-enable

### USG Recovery from Boot Loop
- USG stuck in boot loop from invalid VLAN provisioning
- Factory reset performed on-site
- SSH re-adoption: `set-inform http://72aae5a9-8e9c-42ae-83b6-656a92457b09.unifi-hosting.ui.com:8080/inform`
- USG re-adopted successfully, all subsystems green

### Guest Usergroup QoS Fix
- `sojourn-guest` SSID was on `Default` usergroup (unlimited bandwidth)
- Switched to `guest` usergroup (`63762b33922fab0fb767fa76`) with `qos_rate_max_down: 5000` / `qos_rate_max_up: 5000`
- Guest bandwidth now actually capped at 5/5 Mbps

### Portal `ec_enabled` Fix
- External captive portal (`ec_enabled: true`) was overriding internal portal, showing blank page
- Set `ec_enabled: false` so internal Angular portal renders with custom branding
- Portal now shows: "Welcome to Sojourn Church", terms checkbox, "Connect to Internet"

### Key Lessons
1. **VLAN-only != corporate** — vlan-only creates tag, no DHCP/routing. Need corporate purpose for functional WiFi VLANs.
2. **UniFi controller bug** — static WAN + USG 3P = `WanIpOverlapped` on ANY corporate network creation via API.
3. **Cookie reuse beats re-auth** — Every CLI login = rate limit hit. Persist and reuse cookies.
4. **`ec_enabled` disables internal portal** — Must be `false` for branded captive portals to render.
5. **Guest bandwidth = usergroup QoS** — `download_limit`/`upload_limit` in guest_access are unused. Real enforcement is usergroup `qos_rate_max_down`/`qos_rate_max_up`.
6. **USG recovery via SSH set-inform** — Factory reset → SSH ubnt/ubnt → `set-inform <hosted-url>` → adopt. Raw IP doesn't work for cloud-hosted controllers.
7. **qwen3.5:27b is ~5-10x lighter than kimi-k2.6** — Same tool support and thinking tags. Great for scheduled writing crons.
