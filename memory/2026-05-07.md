## Discord debug session — May 7 afternoon

### Problem: "Nova is typing" but no text response in Discord guild channels

Root cause identified: **guild channel replies are private by default** in OpenClaw Discord. The `message` tool must be explicitly called, or `messages.groupChat.visibleReplies` must be set to `"automatic"`.

Current config has:
- `streaming.mode: "off"` (single final reply)
- **No `messages.groupChat.visibleReplies`** (defaults to private only)

Fix written to `nova-discord-visible-replies.json` but couldn't apply due to memory flush restriction. Need to apply after flush.

### Earlier findings:
1. **Orphan process killed** — PID 17884 was an old gateway process that survived the supposed "kill", causing singleton contention in `sharedGatewayIdentifyLimiter`.
2. **Dedicated Discord agent added** — `agent:discord` created so Discord doesn't queue behind webchat sessions.
3. **Event loop starvation** — `eventLoopDelayMaxMs` hitting 9000ms+ prevents model responses from completing.
4. **Standalone test scripts work** — raw WebSocket to Discord gateway connects in <2s, proving token/network/DNS all valid.
5. **Plugin's `ws.default` issue** — In ESM `import * as ws`, `ws.default` is the constructor. In CJS `require('ws')`, `ws.default` is `undefined`. Plugin bundles `import * as ws` syntax. If transpiled to CJS at runtime, this could cause issues.
